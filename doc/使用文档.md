# hightorque_robot 使用文档

本文档面向机器人、机械臂和其他运动设备的应用开发者。项目的主要用途是作为底层 C++ 电机控制库：应用程序负责规划目标位置，`hightorque_robot` 负责通过通信板向电机发送控制命令，并读取电机反馈。

文档只介绍使用 SDK 所需的内容，不要求读者了解通信协议或库的内部实现。

## 1. 先了解三件事

1. 这是一个会控制真实电机的库，不是仿真程序。创建 `Robot` 或 `CanPort` 时就会打开通信板并访问电机。
2. 项目使用 C++11。项目的 CMake 目标已经声明了 C++11 要求，应用工程通常不需要再单独给 `hightorque_robot` 添加 C++ 标准设置。
3. `stop()` 是发送给电机的控制命令，不能替代急停按钮、断电开关或机械限位。第一次测试前，请确保设备有可以立即断电的安全措施。

如果只想先确认程序能否编译，可以只执行编译步骤，不连接电机运行示例。

## 2. 5 分钟快速上手

下面的流程只使用一个通信板和一个电机。第一次测试不要直接使用多电机配置。

### 2.1 测试前准备

- 固定好电机和机械结构，确认电机运动时不会夹伤人员或撞击设备；
- 准备好急停或断电手段；
- 只连接一个通信板和一个电机；
- 确认电机 ID 是 `1`，通信板能被系统识别；
- 第一次运动使用较小的速度、加速度和位置范围。

通信板需要能被 USB 枚举，并具有以下设备标识：

```text
VID:PID=CAF1:FFFF
```

Linux 下如果设备能看到但程序打不开，先检查当前用户是否有权限访问对应串口，通常需要加入 `dialout` 组。

### 2.2 编译库和示例

在项目根目录执行：

```bash
mkdir -p build
cd build
cmake .. -DCMAKE_BUILD_TYPE=Release \
         -DCMAKE_CXX_STANDARD=11 \
         -DHIGHTORQUE_BUILD_DEMO=ON
cmake --build . -- -j4
```

编译成功后，静态库和示例程序位于 `build/`：

```text
build/libhightorque_robot.a
build/motors_feedback
build/motors_move_zero
```

在 Windows 下可以使用：

```powershell
cmake .. -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_STANDARD=11 -DHIGHTORQUE_BUILD_DEMO=ON
cmake --build . --config Release
```

### 2.3 先做“只读反馈”测试

保持电机不运动，在 `build/` 目录执行：

```bash
./motors_feedback
```

这个示例只请求并打印电机反馈，不会下发位置、速度或力矩目标。正常情况下可以看到类似输出：

```text
ID:  1, mode: ..., fault:  0, pos: ..., vel: ..., tor: ...
```

重点检查：

- `ID` 是否是预期的电机 ID；
- `fault` 是否为 `0`；
- `pos` 是否是实际反馈，而不是初始无效值 `999.0`；
- 反馈是否持续刷新。

让程序运行几秒后按 `Ctrl+C`。该示例会尝试发送停止命令再退出。

### 2.4 做第一次低速运动测试

确认反馈正常后，检查机械结构周围没有障碍物，再执行：

```bash
./motors_move_zero
```

这个示例会持续向电机发送“运动到位置 `0`”的目标，默认参数为：

```text
目标位置：0 rad
速度上限：0.314 rad/s
加速度：  3.14 rad/s²
```

请在第一次运行时观察电机是否按预期运动。发现方向、位置或声音异常时，立即使用急停或断电。测试结束按 `Ctrl+C`，示例会执行 `stop()` 和 `send()`。

`motors_run` 会让电机在 `+0.314 rad` 和 `-0.314 rad` 之间往复运动，不建议把它作为第一次运动测试。

### 2.5 最小应用程序

确认示例工作后，可以在自己的程序中按下面的模式使用 SDK：

```cpp
#include "robot.h"

#include <chrono>
#include <thread>

int main()
{
    // 从 build/ 目录运行时，这个路径指向项目中的默认配置。
    Robot robot("../robot_param/robot_config.yaml");

    // 连续发送 3 秒的低速位置目标。
    for (int i = 0; i < 3000; ++i)
    {
        robot.pos_vel_acc(
            1,       // 通信板 ID
            1,       // 电机 ID
            0.0f,    // 目标位置，rad
            0.1f,    // 速度，rad/s
            0.5f     // 加速度，rad/s²
        );
        robot.send();
        std::this_thread::sleep_for(std::chrono::milliseconds(1));
    }

    // 停止命令写入发送缓存后，还必须调用 send()。
    robot.stop();
    robot.send();
    return 0;
}
```

控制循环中通常每次都按以下顺序处理：

```text
读取或计算目标 -> 设置控制目标 -> send() -> 等待下一个周期
```

如果需要反馈，则在循环中调用 `request_motor_state()`，然后读取 `get_motor_state()` 返回的状态。

## 4. 编译 C++ 库

### 4.1 只编译静态库

不需要项目自带示例时，在项目根目录执行：

```bash
mkdir -p build
cd build
cmake .. -DCMAKE_BUILD_TYPE=Release \
         -DCMAKE_CXX_STANDARD=11 \
         -DHIGHTORQUE_BUILD_DEMO=OFF
cmake --build . -- -j4
```

生成的库文件是：

```text
build/libhightorque_robot.a
```

### 4.2 在其他 CMake 项目中使用

推荐把本项目作为子目录加入应用工程：

```cmake
add_subdirectory(path/to/hightorque_robot)

add_executable(my_robot main.cpp)
target_link_libraries(my_robot PRIVATE hightorque_robot)
```

`hightorque_robot` 会把自己的公共头文件、串口库、YAML 库和线程依赖传递给应用目标。应用程序只需要链接 `hightorque_robot`，不需要手动逐个添加这些依赖。

项目最低要求 C++11。支持 C++11 的 GCC、Clang 或 MSVC 均可使用；C++98/03 不在支持范围内。

## 5. 配置一个机器人

`Robot` 使用两个 YAML 文件：

- `robot_config.yaml`：入口文件，使用 `param_file` 指向详细参数文件；
- 详细参数文件：定义机器人、通信板和电机。

### 5.1 最小配置

入口文件示例：

```yaml
param_file: "motors.yaml"
```

详细参数文件示例：

```yaml
robot:
  robot_name: "Single_Motor"
  canport_num: 1
  canport:
    canport_1:
      canport_id: 1
      motor_num: 1
      motor:
        motor_1:
          id: 1
          name: "left_joint"
```

建议把两个文件放在同一个目录中，例如：

```text
config/
├── robot_config.yaml
└── motors.yaml
```

`param_file` 使用相对路径时，是相对于 `robot_config.yaml` 所在目录解析的，不依赖程序从哪个目录启动。仓库中的 `robot_param/robot_config.yaml` 和 `robot_param/1dof_params.yaml` 可直接作为单电机配置参考。

### 5.2 字段说明

| 字段 | 说明 |
| --- | --- |
| `robot.robot_name` | 机器人名称，主要用于日志显示 |
| `robot.canport_num` | 通信板数量 |
| `robot.canport` | 通信板配置集合 |
| `canport_id` | 通信板编号，从 `1` 开始 |
| `motor_num` | 当前通信板上的电机数量 |
| `motor` | 电机配置集合 |
| `id` | 电机 ID，范围 `1~30` |
| `name` | 电机名称，例如 `left_shoulder`、`joint_1` |

`canport_1`、`motor_1` 只是 YAML 中用于组织内容的键名，真正用于通信的是 `canport_id` 和电机 `id`。

请保证以下数量与实际配置一致：

- `canport_num` 等于通信板数量；
- 每个 `motor_num` 等于该通信板列出的电机数量；
- 同一通信板上的电机 ID 不重复，并且在 `1~30` 范围内；
- `canport_id` 按通信板编号从 `1` 开始。

多通信板配置可以参考 `robot_param/70dof_params.yaml`。

### 5.3 在程序中指定配置

```cpp
#include "robot.h"

int main()
{
    Robot robot("/absolute/path/to/robot_config.yaml");
    // 后续使用 robot.motors 或 Robot 的控制接口。
}
```

不传路径的 `Robot()` 会读取 `../robot_param/robot_config.yaml`。这个默认路径相对于程序的当前工作目录，因此运行仓库示例时建议先 `cd build`。

## 6. 选择使用哪一层接口

### 6.1 `Robot`：推荐给机器人和机械臂应用

`Robot` 根据 YAML 统一管理多个通信板和电机。应用程序可以通过通信板 ID 和电机 ID 控制单个电机，也可以遍历 `robot.motors` 控制配置中的全部电机。

```cpp
#include "robot.h"

Robot robot("../robot_param/robot_config.yaml");

robot.pos_vel_acc(1, 1, 0.0f, 0.1f, 0.5f);
robot.send();

robot.request_motor_state();
motor_state_t* state = robot.get_motor_state(1, 1);
if (state != nullptr)
{
    // state->position、state->velocity、state->torque
    // state->fault 分别表示位置、速度、力矩和电机错误码。
}

robot.stop();
robot.send();
```

`Robot` 常用接口：

| 接口 | 作用 |
| --- | --- |
| `position(port, id, pos)` | 位置控制 |
| `velocity(port, id, vel)` | 速度控制 |
| `torque(port, id, tqe)` | 力矩控制 |
| `vel_acc(port, id, vel, acc)` | 速度/加速度控制 |
| `pos_vel_acc(port, id, pos, vel, acc)` | 位置/速度/加速度控制 |
| `pos_vel_MAXtqe(port, id, pos, vel, max_tqe)` | 带最大力矩限制的位置控制 |
| `pos_vel_tqe_kp_kd(...)` | 位置、速度、力矩、Kp、Kd 控制 |
| `request_motor_state()` | 请求全部电机反馈 |
| `get_motor_state(port, id)` | 获取一个电机反馈 |
| `get_can_port_state(port)` | 获取通信板 FDCAN 状态 |
| `stop()` / `brake()` / `reset()` | 控制全部电机 |
| `stop(port, id)` / `brake(port, id)` / `reset(port, id)` | 控制单个电机 |
| `motor_zero_pos_reset()` | 执行电机零位重置流程 |
| `send()` | 发送当前控制缓存 |

除请求反馈和零位重置流程外，控制接口通常只是更新发送缓存。调用 `stop()`、`brake()` 或 `reset()` 后，也必须调用 `send()`。

### 6.2 `Motor`：适合按关节对象编写控制循环

`Robot::motors` 是配置文件中所有电机的句柄集合：

```cpp
Robot robot("../robot_param/robot_config.yaml");

for (Motor& motor : robot.motors)
{
    motor.pos_vel_acc(0.0f, 0.1f, 0.5f);
}
robot.send();
```

`Motor` 不拥有 `CanPort`，只是一个轻量句柄。通过 `CanPort` 手动创建 `Motor` 时，必须保证 `CanPort` 的生命周期长于 `Motor`。

### 6.3 `CanPort`：不使用 YAML 时使用

如果应用已经自己管理电机配置，可以直接创建一个通信板：

```cpp
#include "canport.h"

int main()
{
    CanPort can_port(1, {1, 2});

    can_port.pos_vel_acc(1, 0.0f, 0.1f, 0.5f);
    can_port.send();

    can_port.request_motor_state();
    motor_state_t* state = can_port.get_motor_state(1);

    can_port.stop();
    can_port.send();
    return 0;
}
```

第一个参数是通信板 ID，第二个参数是这块通信板上的电机 ID 列表。也可以使用名称映射：

```cpp
std::map<uint8_t, std::string> motors;
motors[1] = "left_joint";
motors[2] = "right_joint";
CanPort can_port(1, motors);
```

## 7. 单位、反馈和控制周期

位置、速度和加速度的默认单位为：

| 数据 | 单位 |
| --- | --- |
| 位置 | `rad` |
| 速度 | `rad/s` |
| 加速度 | `rad/s²` |
| 力矩 | 由电机协议定义，使用前请结合电机型号确认 |

一个常见的 1 kHz 控制循环如下：

```cpp
while (running)
{
    // 1. 根据规划器或上层控制器计算目标
    motor.pos_vel_acc(target_pos, target_vel, target_acc);

    // 2. 发送本周期目标
    robot.send();

    // 3. 请求并读取反馈（也可以按需要降低读取频率）
    motor.request_motor_state();
    motor_state_t* state = motor.get_motor_state();

    // 4. 等待下一个控制周期
}
```

状态由 SDK 的接收线程更新。`get_motor_state()` 返回内部状态指针，不转移所有权；不要把这个指针长期保存到 `Robot` 销毁之后。如果要跨线程或长期使用，请及时复制结构内容。

`motor_state_t` 常用字段：

| 字段 | 含义 |
| --- | --- |
| `mode` | 电机当前模式 |
| `fault` | 电机错误码，`0` 通常表示正常 |
| `position` | 当前位置 |
| `velocity` | 当前速度 |
| `torque` | 当前力矩 |
| `fw_version` | 电机固件版本 |
| `model` | 电机型号 |
| `name` | 配置中的电机名称 |

初始状态中的 `position=999.0` 表示暂时没有收到有效反馈，不应把它当成真实位置。

示例都需要真实通信板和电机。C++ 示例由 CMake 生成到 `build/`，应从该目录运行：

```bash
cd build

```

Python 示例与 C++ 示例使用相同的文件名、类名、方法名、变量名和控制流程。Python

## 9. 停止程序和安全退出

推荐在应用退出前执行：

```cpp
robot.stop();
robot.send();
```

如果只停止某一个电机：

```cpp
robot.stop(can_port_id, motor_id);
robot.send();
```

项目中带有 `SIGINT` 处理的循环示例可以使用 `Ctrl+C` 退出，并在退出前发送停止命令。停止命令通过通信链路发送，通信中断、程序卡死或控制器异常时不保证能够代替硬件急停，因此机械设备必须保留独立的安全停止手段。

## 10. 常见问题

### 10.1 `no comm board serial ports found`

SDK 没有找到设备标识为 `CAF1:FFFF` 的通信板。依次检查：

- 通信板是否连接并供电；
- USB 线是否支持数据传输；
- 操作系统是否识别到串口；
- Linux 当前用户是否有串口访问权限；
- 设备的 VID/PID 是否确实为 `CAF1:FFFF`。

### 10.2 `not enough serial ports`

程序请求的通信板编号超过了自动检测到的数量。检查通信板连接数量、`canport_id` 和 `robot.canport_num`。

多个通信板的编号按 SDK 枚举顺序分配。Windows 下 SDK 会对符合条件的设备排序；如果设备顺序很重要，建议在实际目标机上固定并验证 USB 连接方式。

### 10.3 `serial open err` 或 Linux 权限错误

先确认串口设备存在，再检查权限。例如当前用户不在 `dialout` 组时，可以按系统规范加入该组并重新登录。不要为了测试长期使用过大的串口权限。

### 10.4 `comm board version too low`

通信板固件版本低于 `v6.0.0`。升级通信板固件后再使用当前 SDK。

### 10.5 找不到 YAML 文件

配置路径和 `param_file` 路径都需要指向实际文件。运行仓库默认示例时使用：

```bash
cd build
./motors_feedback
```

自己的应用建议传入绝对配置路径，或始终从固定工作目录启动，避免依赖当前工作目录。

### 10.6 配置能解析但电机数量不正确

检查：

- `robot.canport_num` 是否等于通信板数量；
- 每个 `motor_num` 是否等于该通信板下的电机数量；
- 电机 `id` 是否唯一且在 `1~30`；
- `canport_id` 是否从 `1` 开始；
- 应用程序使用的通信板 ID 和电机 ID 是否与 YAML 相同。

### 10.7 `fault` 非零或位置显示 `999.0`

`fault` 非零表示电机报告了异常，应先停止运动并根据电机手册确认错误含义。`position=999.0` 通常表示一段时间没有收到有效反馈，请检查电机供电、通信线、通信板状态和电机 ID。

### 10.8 控制命令没有效果

确认控制调用后执行了 `send()`：

```cpp
robot.pos_vel_acc(1, 1, 0.0f, 0.1f, 0.5f);
robot.send();
```

`position()`、`velocity()`、`torque()` 等接口只更新当前发送缓存，不调用 `send()` 就不会真正发送新的控制目标。

### 10.9 程序启动后直接退出

SDK 初始化失败时可能直接结束进程，而不是抛出 C++ 异常。请查看终端中最后一条错误信息，重点检查通信板、固件版本、串口权限、配置文件路径和电机数量。

## 11. 上线前检查清单

在把 SDK 接入机器人或机械臂主控制程序前，建议逐项确认：

- [ ] 已用单电机完成只读反馈测试；
- [ ] 已确认每个电机 ID、通信板 ID 和关节名称；
- [ ] 已为每个关节设置合理的位置、速度、加速度和力矩限制；
- [ ] 控制循环中每个周期都会调用 `send()`；
- [ ] 已处理 `fault`、反馈超时和通信板 FDCAN 状态；
- [ ] 正常退出路径会发送 `stop()` 和 `send()`；
- [ ] 设备有独立于软件的急停或断电手段；
- [ ] 已在低速、低负载和小运动范围下完成验证。
